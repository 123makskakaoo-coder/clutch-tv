# CLUTCH.TV — локальный сайт в стиле HLTV

Сайт про Counter-Strike: новости, матчи, рейтинг команд и турниры. Это **своя** реализация
похожей структуры, а не копия HLTV.org: чужие статьи, логотип и данные не используются,
интернет для работы не нужен.

## Как открыть

Дважды кликните `index.html` — всё работает прямо с диска (Chrome, Edge, Firefox).

Если нужно, чтобы сайт открывался по адресу вида `http://localhost:8000`:

```
cd clutch-tv
python -m http.server 8000
```

## Как добавить новость

1. Откройте `admin.html` (кнопка «АДМИНКА» в меню) и введите ключ — см. «Доступ к админке».
2. Заполните «Заголовок» и «Дата и время» — они обязательные, остальные поля по желанию.
3. Пустая строка в поле «Текст новости» = новый абзац.
4. Нажмите «Добавить». Запись сразу появляется на главной и в «НОВОСТИ».
5. «Изменить» правит запись, «Удалить» убирает её, ссылка «Редактировать» внизу новости ведёт
   сразу в форму с уже заполненными полями.

Те же вкладки работают для матчей, команд и турниров: матч с статусом «Live» подсвечивается,
у анонса считается время до начала, рейтинг сортируется по очкам, поле «Изменение позиции»
даёт стрелки ▲/▼.

## Профили игроков и команд

Страница игрока существует для любого никнейма, который написан в ростере команды, — вводить
его отдельно не нужно. Открывается кликом по нику в составе, по команде — в матчах, сетках и
рейтинге, страница команды кликом по её названию.

Вкладка «ИГРОКИ» в админке только дополняет то, что уже собрались из составов: настоящее имя,
страна, возраст, роль, рейтинг 2.0, фото и история составов (строка вида
`Team Spirit | Aug 2021 — May 2023`). Пустые поля на странице просто не показываются.
Если поменять никнейм в профиле, он правится и в ростере команды — страница не разъезжается.
Удалить можно только заполненный профиль; пустой убирается строчкой ника из состава.

Достижения нигде не вводятся руками: места, вылеты и швейцарские счётки считаются по сеткам,
которые вы и так заполняете во вкладке «Сетки».

## Запас команд

Состав и запас — две разные строки команды. Правится во вкладке «Запас» админки: выбираете
команду чипом, и ниже две таблицы — «Основной состав» с кнопкой **«В запас»** и «Запас» с кнопками
**«В состав»** и **«Убрать»**. Нажатие сохраняет сразу, запятые писать не нужно. Полем
«Запас через запятую» в карточке команды можно пользоваться параллельно — это те же данные.
Ника, который уже числится за другой командой, в запас второй команды не пускают: страница
игрока показала бы не ту команду. Сначала уберите его оттуда.
На сайте запас виден на вкладке «Запас» (`bench.html`), там же ссылки на профили.

## Оверлей для стрима (CS2 GSI)

Поверх игры в OBS показывается счёт команд, таймер раунда, карта, номер раунда и панели
игроков: здоровье, броня, деньги, оружие, киллы/смерти. Данные приходят прямо из CS2,
счёт двигается сам — руками вводить ничего не нужно. Это работает только на вашем ПК и
никуда не публикуется: папка `stream/` в `dist` не попадает.

Нужен Java (у вас уже стоит — та же, что для сервера Minecraft). Проверить: `java -version`.

1. Дважды кликните `stream.cmd` — окно с надписью «CLUTCH.TV GSI» должно оставаться открытым
   всё время стрима. Закрываете окно — оверлей гаснет.
2. В OBS: «Источник» → «Браузер» → URL `http://127.0.0.1:8010/`, ширина 1920, высота 1080.
   Фон сам прозрачный, ничего дополнительно включать не надо.
3. CS2 сам стучится на этот адрес. Конфиг лежит в двух местах, потому что игра по факту
   сканирует только `Counter-Strike Global Offensive\game\csgo\cfg\` (там же живёт конфиг Medal):
   `...\cfg\gamestate_integration_clutch-tv.cfg` и `...\cfg\gamestate_integration\gamestate_integration_clutch-tv.cfg`.
   CS2 читает их только при запуске, поэтому после любой правки — полностью закрыть игру и открыть снова.
4. Подпишите сверху, что показывать: `stream\stream.json` — `event` (название турнира),
   `stage` (стадия), `bo` (BO1/BO3), `teamA` и `teamB` (если хотите свои названия вместо тех,
   что отдаёт игра), `roundTime` — длина раунда в секундах (115 = 1:55, стандарт матчмейкинга).
   После правки достаточно обновить источник в OBS кнопкой «Обновить».

Про часы раунда: CS2 в GSI не присылает остаток времени (в пакете есть только фаза), поэтому
оверлей сам отсчитывает `roundTime` от момента, когда фаза стала `live`. Если обновить источник
посреди раунда, таймер догонит со следующего раунда. Когда обычное время вышло, а раунд всё ещё
идёт — на месте часов будет «ЭКСТРА», потому что реальный овертайм игра тоже не считает.

Важно про панели игроков: игра отдаёт статы всех десяти только когда вы смотрите матч
наблюдателем (GOTV) или с сервера. Если вы сами играете, в оверлее будет ваша строка —
остальные останутся пустыми, и оверлей сам напишет об этом внизу экрана.

Число «зрителей» из скриншота — это счётчик Twitch, CS2 его не отдаёт, поэтому в оверлее его нет.

Не видно ничего: откройте в браузере `http://localhost:8010/` — там либо оверлей, либо
сообщение «Сервер не отвечает» (не запущен `stream.cmd`). Если страница открылась, но счёт
нулевой и внизу красная плашка — CS2 не шлёт данные: проверьте шаг 3 и что матч активен.

## Скобки (плей-офф, швейцарка, двойная)

Смотреть: кликните название турнира в любом списке (`events.html`, «Турниры» на главной,
колонка «Турнир» в матчах) — откроется `event.html?id=...` со всей информацией: карточка
ивента, **выбранная сетка этого турнира**, его матчи и новости. Над сеткой идут кнопки с
названиями сеток этого турнира — нажали «Группа A» и смотрите только её, «Все сетки»
показывает сразу все. Ссылка на конкретную сетку: `event.html?id=...&bracket=...`.
Если у турнира есть только швейцарка или только двойная, среди кнопок появляется
«Добавить плей-офф» — одним кликом создаёт сетку с выбыванием нужного размера.
Отдельная страница `bracket.html` (пункт меню «СЕТКИ») и главная — под блоком матчей:
панель «Скобки» с вкладками-чипами по названию сетки («Плей-офф», «Группа A, швейцарка
до 3 побед»...). Нажали вкладку — открылась именно эта сетка, а в адресе стоит
`?bracket=...`, чтобы ссылку можно было кинуть другому. Если у двух сеток одинаковое
название, на вкладке дописывается сначала турнир, потом формат, потом размер
(«Плей-офф · 8 команд»), чтобы вкладки не сливались в одну. Ссылка
«все сетки →» ведёт на общий список. Кнопки на странице турнира открывают нужную вкладку
админки (`admin.html?tab=matches`, `?tab=brackets`, `?tab=events`).

Внешность сетки: у каждой панели заголовок с форматом («Турнирная сетка с выбыванием после
первого поражения», «... с верхней и нижней сеткой», «Швейцарская система до 3 побед») и
стрелкой ▲ — панель сворачивается кликом. У команд есть монограммы (короткое имя из
рейтинга, цвет подбирается по названию), победитель подсвечен зелёной полосой слева и
помечен → (перешёл дальше), проигравший приглушён, а в верхней части двойной сетки ещё и ↓
(упал в нижнюю). Матч может быть «в эфире» — тогда у него красная рамка
и плашка Live, а при заполненной ссылке на трансляцию появляется «Смотреть ▶».

Раунды подписаны как в больших турнирах: `Четвертьфиналы`, `Полуфиналы`, `Гранд-финал`
(старая сетка на 16 команд сверху добавляет `1/8 финала` — новые такие не создаются),
матч за 3-е место — блок
«Матч за 3-е место, решающий исход» с раундом `дополнительный раунд`. Названия по-прежнему
правятся в админке.

Три формата (создаются во вкладке «Сетки» админки):

- **Одиночная (до первого поражения)** — 4 или 8 команд. Победитель каждого матча
  автоматически переходит в следующий раунд, опция «Матч за 3-е место» добавляет отдельную
  пару для проигравших в полуфинале.
- **Двойная (верхний + нижний кронштейн)** — 4 или 8 команд. Проигравшие в верхней сетке
  падают в нижнюю (`Нижний раунд 1`, `Нижние полуфиналы`, `Нижний финал`), победитель
  нижней играет `Гранд-финал` против победителя верхней.
- **Швейцарская (до 3 побед)** — 8 или 16 команд. Доска из 15 колодок счёта в пять колонок,
  как на HLTV: `0-0` · `1-0` `0-1` · `2-0` `1-1` `0-2` · `3-0` `2-1` `1-2` `0-3` ·
  `3-1` `3-2` `2-2` `1-3` `2-3`. Колодки `3-0`, `3-1`, `3-2` зелёные — оттуда команды
  выходят дальше, `0-3`, `1-3`, `2-3` красные — вылет. Пары составляете сами
  («Добавить матч» в нужной группе, «Удалить матч» убирает лишнее) или доверяете сайту —
  кнопки «Перезагрузить пары» и «Высшее семя». Таблица побед и поражений со статусами
  «Прошла дальше / Играет / Вылетела» считается по всем сыгранным матчам.
  Колодка `0-0` (первый круг) создаётся сразу с нужным числом пустых матчей. У остальных
  колодок места тоже рисуются заранее — сколько команд должно в них оказаться при таком
  размере сетки (для 16 команд: `0:0` — 8 строк, `1:0` и `0:1` по 4, `2:0`/`1:1`/`0:2`
  2·4·2, `2:1` и `1:2` по 3, `2:2` 3). Пустое место — такой же ряд с двумя щитами `?`,
  поэтому колонки доски одинаковые по высоте, а не «в одной восемь, в другой одна».
  У доски два вида, переключаются кнопкой над ней: **краткий** — как на HLTV, в каждой
  строчке только два логотипа-щита рядом (проигравший приглушён), счёт мелким чипом
  справа, у Live-матча красная рамка; и **детальный** — обычные двухстрочные блоки с
  флагами. Выбор запоминается в `localStorage` (`clutch-tv.swissView`) и действует на
  всех страницах. Подпись счёта (`0:0`, `1:0`...) стоит над рамкой колодки, а зелёные
  и красные блоки — это не матчи, а списки команд, которые закончили с таким счётом:
  их логотипы сетка берёт из таблицы побед и поражений, пустые места показывает щитами
  с `?`. Пары стоящих рядом блоков (`3:1` рядом с `3:2`, `1:3` рядом с `2:3`) сидят в одной
  строке, как на HLTV, а не столбиком друг под другом. Справа от каждой боевой колодки стоят стрелки `»»`: зелёная — победители уходят
  вверх по счёту, красная — проигравшие падают вниз (`2:1` → `3:1` и `2:2`). У зелёных и
  красных финальных блоков стрелок нет — там турнир уже закончен. В подписи колодки
  появляется чип `TBD`, пока её ещё не наполнили предыдущие круги. Колодки в колонке
  идут лесенкой вниз — доска читается по диагонали, как на HLTV.

Как заполнять:

1. Выбрать турнир, формат, число команд и при желании название сетки («Плей-офф»,
   «Группа A»...). У одного турнира может быть несколько сеток. Быстрее всего — кнопка
   «Плей-офф 4 / 8»: одиночная сетка с названием «Плей-офф». Круга «1/8 финала» в новых
   плей-офф нет — максимальная автоматическая сетка на 8 команд.
   Плей-офф у турнира бывает **один**: любая сетка «с выбыванием» считается его
   плей-офф, как бы она ни называлась и сколько бы команд в ней ни было. Поэтому
   «Плей-офф 4 / 8» не создаёт вторую, а открывает уже существующую — новую сетку этого
   же турнира можно сделать через формат («Создать сетку»).
   Рядом «Плей-офф всем турнирам» — ставит такую сетку каждому турниру, у которого её
   ещё нет (на 4 команды, если в карточке 4 или меньше, иначе на 8). Новый турнир
   получает свой плей-офф автоматически при добавлении, а если он появился позже или
   потерялся — достаточно сохранить турнир во вкладке «Турниры» ещё раз.
   Ниже — вкладками все сетки сайта («Редактировать сетку»): нажали «Группа B, швейцарка
   до 3 побед» — редактор открыл именно её, любую, не только плей-офф. Рядом кнопка
   «Убрать дубликаты» — удаляет повторные сетки с тем же турниром, названием и форматом,
   оставляя ту, где сыграно больше матчей (спрашивает перед удалением).
2. «Создать сетку» — если сетка с такими параметрами уже есть, она просто откроется.
3. Команды вписываются там, где поля активны: первый раунд в одиночной, `Первый раунд`
   в двойной, любая группа в швейцарке. Остальные поля принимают только счёт — команды
   приходят по результатам выше.
4. Вбить счёт. В швейцарке матч сохраняется сам, стоит перейти в следующее поле; в
   плей-офф жмите «Сохранить» — сетка пересчитается вниз до самого финала. Под строкой
   всегда написано, как понимается именно то, что вбито: «победитель: NAVI»,
   «равный счёт — победителя нет», «счёта нет — победителя нет». Приписка
   «· не сохранено» значит, что поле ещё не записано: в одиночной и двойной сетке
   для этого и нужен «Сохранить».
   Победителя не будет, если у выигравшей строки пустая графа команды: имя нужно и у
   победителя, и у проигравшего — иначе результат не попадёт ни в таблицу швейцарки,
   ни в следующую стадию.
5. Поля «время» и «BO» — подписи матча (`18:00 Пятница`, `BO3`), на расчёт не влияют.
   Галочка «в эфире» и поле со ссылкой на трансляцию — там же.
6. «Сбросить счёт» убирает результат, все места ниже по сетке очищаются.
7. Названия раундов правятся в полях над списком матчей (кнопка «Сохранить названия
   раундов»), название сетки — в его поле. «Смотреть на сайте →» открывает готовую сетку.
8. Галочка «Показывать на странице турнира» убирает или возвращает сетку в выбор на
   `event.html?id=...`. На странице появится счётчик «скрыто N из M».
9. В швейцарке пары можно не писать руками: «Перезагрузить пары» рассаживает команды с
   таким счётом в случайном порядке, «Высшее семя» — по рейтингу (сильнейший слева).
   Пары берутся из результатов всех остальных групп, сыгранный счёт выбранной группы
   при этом спросят на перезапись.

Формат у созданной сетки не меняется: для другого формата создайте новую или удалите эту.
Считается по числу карт (2:1, 3:0 и т. п.). Равный или пустой счёт = победителя нет.
Одна команда без соперника = прохождение без игры (bye). Матч за 3-е место доступен для
одиночной сетки и для двойной на 8 команд: в двойной на 4 командах проигравший верхнего
финала и так попадает в нижний.

## Где хранятся данные

В `localStorage` браузера — только на этом компьютере, никуда не отправляется.
Поэтому:

- данные видны в том браузере, где вы их вводили;
- «Очистка истории / данных сайта» их удалит;
- чтобы перенести: `admin.html` → вкладка «Резервные копии» → «Скачать data.json»,
  на другом компьютере там же «Загрузить data.json».

Кнопка «Заменить на примеры» заполняет базу демонстрационными записями, «Удалить всё» чистит.

Если сохранённая база оказалась нечитающейся (битый JSON, повреждённая сетка), сайт не
молча заменяет её пустой: сверху появляется красная плашка, показывается пустая база, а
обычное сохранение выключено, чтобы не перезаписать то, что ещё лежит в браузере. Одна
повреждённая сетка больше не тянет за собой остальные — её оставляют как есть, остальные
работают. Лечится вкладкой «Резервные копии» → «Загрузить data.json». Поэтому и полезно
после крупных изменений жать «Скачать data.json»: файл — единственная копия, которая
переживает чистку браузера.

## Доступ к админке: ключ

Админка больше не открывается просто по ссылке. Первый запуск просит **задать ключ**
(минимум 4 символа), дальше при каждом входе — ввести его. Закрыть админку в своём окне
можно кнопкой «Закрыть админку в этом окне», сменить ключ — во вкладке «Резервные копии»
в блоке «Доступ к админке».

Что честно нужно знать про этот замок:

- ключ хранится отпечатком в этом браузере, самого ключа в файлах сайта нет;
- он убирает кнопку «АДМИНКА» с глаз и не даёт править тому, кто просто открыл ссылку;
- тот, кто умеет читать код страницы, его обойдёт. Настоящий замок — это когда наружу
  уходит только публичная папка `dist`, а в ней `admin.html` и `assets/js/admin.js`
  отсутствуют как файл. Тогда править может только тот, у кого есть исходная папка
  `clutch-tv`.

## Как выложить сайт для всех

Сайт статический: его можно положить на любой бесплатный хостинг, и он заработает.
Но данные живут в `localStorage` вашего браузера, а на хостинге у каждого посетителя
свой пустой `localStorage`. Поэтому сначала выгружаем свою базу:

1. `admin.html` → вкладка «Резервные копии» → «Скачать data.json» (или «Скачать data.js»).
2. Положить файл в `clutch-tv\seed\data.js` (заменить служебный). Если скачался
   `clutch-tv-data.json` — он лежит в `seed\`, и из него собирается `data.js`.
3. Запустить `make-dist.cmd` — он собирает публичную папку `dist` и её точную копию
   `docs` (все страницы, но без админки и без `admin.js`).
4. Выложить: `dist` — на Qoder Sites, `docs` — на GitHub Pages.

Работает так: у посетителя база берётся из `seed/data.js`; если он сам что-то ввёл у себя
и это новее по времени (`updatedAt`) — показывается его, иначе ваш снимок. Вы ничего не
ломаете чужими данными и никто не ломает ваши.

### Кнопка «Загрузить на сайт» — то же самое одним кликом

В админке, во вкладке «Резервные копии», есть кнопка **«Загрузить на сайт»**. Она делает
пункты 1-4 сами: снимок базы ложится в `seed\data.js`, `make-dist.cmd` пересобирает `dist`
и `docs`, а `git` отправляет их на GitHub Pages. Адрес зеркала `qoder.website` кнопкой
не обновляется — там публикация идёт через агента, по слову «передублируй».

Кнопке нужен маленький помощник, потому что браузер сам не умеет ни писать в папку проекта,
ни делать `git push`:

1. Дважды кликните ярлык **«Загрузка на сайт»** на рабочем столе (это `publish.cmd`).
   Окно с надписью «CLUTCH.TV: помощник загрузки на сайт» держите открытым, пока жмёте кнопку.
2. В админке нажмите «Загрузить на сайт» — внизу появится, что именно произошло, и номер коммита.
3. Через 1-3 минуты Pages отдаёт новую базу. Проверка: первая строчка в
   `https://123makskakaoo-coder.github.io/clutch-tv/seed/data.js` — там время вашей выгрузки.

Помощник слушает только `127.0.0.1` на порту `8020` и наружу ничего не открывает. Он же и
страхует: пустую базу, базу без новостей/матчей/команд/турниров/сеток вместо прежних и
демонстрационные примеры он на сайт не пускает и пишет почему. Прежний снимок остаётся в
`publish\data.prev.js`. Без запущенного помощника кнопка честно отвечает, что тот не запущен, —
ничего не ломается и не публикуется.

## Два адреса сайта

- **GitHub Pages** — основной: `https://123makskakaoo-coder.github.io/clutch-tv/`.
  Публикуется папка `docs` из репозитория [clutch-tv](https://github.com/123makskakaoo-coder/clutch-tv).
  Обновление:

  ```
  cd clutch-tv
  ./make-dist.cmd
  git add -A && git commit -m "данные" && git push
  ```

  Через минуту-две Pages отдаёт новую версию (свежий коммит на `main` = публикация).

- **Qoder Sites** — второе зеркало, адрес вида `https://...qoder.website`. Его обновляет
  агент из папки `dist` по слову «переопубликуй».

Лимиты у обоих бесплатные, но не безразмерные: у Qoder Sites есть суточный лимит
просмотров (когда кончается — посетители до сброса видят служебную страницу про исчерпанный
лимит, сам сайт цел), у GitHub Pages лимит на трафик и на размер страницы. Если один адрес
лежит, второй работает.

## Что не попадает в репозиторий

Всё приватное перечислено в `.gitignore`, и GitHub его не увидит никогда:

- `admin.html` и `assets/js/admin.js` — редактор остаётся только на вашем диске;
- `stream/` и `stream.cmd` — оверлей для OBS и приёмник CS2;
- `publish/` и `publish.cmd` — помощник кнопки «Загрузить на сайт» и прежний снимок базы;
- `seed/*.json` — ваши выгрузки `data.json` с полными карточками игроков;
- `dist/` — служебная сборка, в сети лежит её копия `docs`.

На GitHub Pages админку нельзя открыть даже по прямой ссылке: её нет ни в `docs`,
ни в истории коммитов.

Где брать место под сайт:

- **GitHub Pages** — уже подключён, бесплатный для публичного репозитория.
- **Qoder Sites** — публикую прямо здесь, из папки `dist`, доступ по умолчанию приватный,
  публичный нужно включать отдельно.
- **Cloudflare Pages / Netlify** — аккаунт, дальше «перетащить папку» или подключить
  репозиторий. Тарифы бесплатные, точные условия и лимиты проверяйте на их
  сайте: они меняются, и обещать «навсегда бесплатно» за них никто не может.


## Что менять под себя

- Название и меню — массив `NAV` в `assets/js/app.js`, логотип там же в `renderChrome`.
- Цвета — блок `:root` в `assets/css/style.css` (`--accent`, `--bg`).
- Поля форм — объект `SCHEMA` в `assets/js/admin.js`: добавьте `{ key: 'source', label: 'Источник', type: 'text' }`
  в нужный раздел, поле появится в форме и сохранится автоматически.
